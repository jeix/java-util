# PRD (프로젝트 요구사항 정의서)

## 1. 개요

자바 유틸리티 클래스를 개발하고 JUnit으로 검증하기 위한 최소한의 프로젝트 구조를 제공합니다.
빌드 도구가 전역 설치되어 있지 않은 환경에서도 저장소만으로 빌드·테스트가 가능해야 합니다.

## 2. 목표

- 재사용 가능한 자바 유틸리티 클래스를 담을 수 있는 표준 프로젝트 구조 확보
- 외부 라이브러리(lombok, jackson, slf4j) 의존성 사용 기반 마련
- JUnit 기반 테스트 작성·실행 환경 확보
- 문자열·컬렉션 유틸리티와 순서 있는 값 묶음 타입 제공

## 3. 범위

- 포함:
  - 소스/테스트 디렉터리 구조, Maven 빌드 구성
  - 문자열 유틸리티 `s.util.StringUtil`
  - 컬렉션 유틸리티 `s.util.CollectionUtil`
  - 순서 있는 값 묶음 타입 `s.type.tuple.Pair`/`Triplet`/`Quartet`
  - 예제 클래스 `s.Hello`와 각 구성의 테스트
- 제외: 배포 자동화(CI/CD), 외부 서비스 연동, 라이선스 확정

## 4. 기능 요구사항

| ID | 요구사항 |
| --- | --- |
| FR-1 | Java 21로 컴파일되는 `src/main/java` 구조를 가진다. |
| FR-2 | lombok, jackson 의존성을 사용할 수 있다. |
| FR-3 | 유틸리티 클래스와 그 테스트 클래스를 작성할 수 있다. |
| FR-4 | 전역 빌드 도구 없이 저장소 내 래퍼로 빌드·테스트할 수 있다. |
| FR-5 | 구조 확인용 `s.Hello`와 `s.HelloTest`를 제공한다. |
| FR-6 | 문자열 유틸리티 `s.util.StringUtil`(판별/기본값/선택/변환/패딩/조인·분리)을 제공한다. |
| FR-7 | 컬렉션 유틸리티 `s.util.CollectionUtil`(리스트·맵 판별, 집합 연산, 슬라이스, 색인·분류, 변환)을 제공하며 결과 컬렉션은 불변이다. |
| FR-8 | 순서 있는 값 묶음 타입 `s.type.tuple.Pair`/`Triplet`/`Quartet`를 제공하고, JSON 직렬화 키로 `ord1`~`ordN`을 사용한다. |
| FR-9 | 각 유틸리티/타입에 정상 케이스 1개 이상, 경계/실패 케이스 1개 이상의 테스트를 제공한다. |
| FR-10 | 테스트 클래스는 Lombok `@Slf4j`로 로깅할 수 있다. |

## 5. 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 | 소스 인코딩은 UTF-8, 컴파일 대상은 Java 21이다. |
| NFR-2 | 이 브랜치와 무관한 파일·디렉터리는 git에 추가하지 않는다. |
| NFR-3 | 테스트는 `./mvnw test` 한 번으로 실행된다. |
| NFR-4 | 유틸리티 메서드는 파라미터를 선검사해 조기 반환하고, 중복 기능은 기존 메서드를 재사용한다. |
| NFR-5 | 같은 기능의 루프/대체 구현(Stream·정규식)을 이중화한 경우 `if/else`로 들여쓰기를 맞추고 실행 시 무작위로 분기한다. |

## 6. 제약 사항

- JDK 21 사용
- 전역 Maven/Gradle 미설치 → Maven Wrapper 사용
- 의존성 최초 다운로드를 위한 네트워크 필요

## 7. 완료 기준

- `./mvnw test`가 성공하고 전체 테스트가 통과한다.
- README 및 `docs/` 문서로 구조와 사용법이 설명된다.
